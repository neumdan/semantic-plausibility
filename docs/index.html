2. Select your input

Use the same pipeline.toml. input.columns maps each semantic role on the left to your column on the right.

InputSettingsWorking recipe
Individual CSVtype="csv", granularity="individual"Three values → one grouped set
Aggregate CSVtype="csv", granularity="distinct"Counts and numeric statistics
FHIR JSON / Bundle / NDJSONtype="fhir_file"Native fields; TORCH/CQL server export
SQLite / PostgreSQL / CDS Hubtype="sqlite" or "postgres"; table + columnsRead-only database examples

Statistics are numbers. Example: mean=14, sd=1, min=12, max=16, unit_code=g/dL. The one measurement unit applies to all these statistics. Separate reference-unit columns describe a different reference interval unit when supplied.

output.mode="distinct" aggregates individual measurements for evidence research and pools compatible disjoint summary groups. mode="items" retains IDs for individual A1 review. Names, specimen, method, units and reference qualifiers remain in the group context.

Read the report

Conditional match: “If the intended system is LOINC, 2823-3 is valid.” A matching name and compatible unit strengthen the finding: code → code + name → code + name + unit. These are ordered evidence levels. Missing source systems and specimen stay absent until confirmed. Every recommendation includes a short Why and its sources.

ScopeWhat it tells you
Profile element QCImplemented element, terminology and binding checks; full FHIR validation is separate
Code + system + name + contextIdentity match and supplied specimen/method
Values + unit + unit systemNumeric format and unit membership
Code–quantity compatibilitySupported unit for the code, including conversion requirements
Whole set + reference/evidenceCombined consistency and sourced physiological evidence for expert review

Each scope reports its result, completeness and reason. A complete set can contain errors. Conditional terminology agreement does not establish physiological plausibility. CSV, HTML and audited evidence use the same assessment. Output columns and status meanings.

5. Models and persistent services

Set models.local.model in TOML. The template uses ministral-3:3b. Select the native endpoint with base_url, the container endpoint with container_base_url.

podman-compose --profile research up -d ollama
podman-compose --profile research run --rm model-init
podman-compose --profile research run --rm catalog-init
podman-compose --profile research run --rm research-evidence research-evidence --scope studies --report output/01-lookup.csv --out output/04-evidence.csv

model-init downloads missing weights into the persistent Ollama volume. catalog-init acquires official UCUM candidate files for research. Use your loaded local service with runtime="external", its base URL and actual model ID.

Architecture and decisions

Python retrieves source text and verifies claims. Ollama performs local inference. Full validation applies to complete FHIR files or FHIR-in-CSV; scalar inputs keep a separate not-applicable outcome when validation is selected.
